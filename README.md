# Neptun Alerts & Galaxy Watch Complication

Мультимодульний Android-застосунок та застосунок для смарт-годинників Samsung Galaxy Watch (Wear OS 3.0+), призначений для оперативного відстеження повітряних тривог в Україні у реальному часі за даними відкритого сервісу [NEPTUN](https://neptun.in.ua/).

---

## Можливості та реалізована функціональність

### 1. Додаток для смартфона (`:mobile`)
- **Багатопрофільний моніторинг (Multi-Profile)**: створення та керування кількома незалежними профілями спостереження (для різних областей чи районів).
- **Вибір регіону / району**: повний довідник 25 областей України з деталізацією до районів за новим адміністративним устроєм. Можливість відстежувати як область цілком, так і конкретний район.
- **Гнучкі сповіщення для кожного профілю**:
  - Окремі перемикачі звуку та вібрації при оголошенні тривоги.
  - Окремі перемикачі звуку та вібрації при відбої тривоги.
  - Вибір індивідуальної мелодії для тривоги та для відбою через системний Ringtone Picker або використання системного сигналу за замовчуванням.
  - Виділені канали сповіщень для кожного профілю.
- **Фільтрація переходів станів**: сповіщення надсилаються виключно при реальній зміні статусу (початок тривоги або відбій), що запобігає повторним помилковим спрацьовуванням при отриманні проміжних зрізів даних.
- **Рівні загрози**:
  - 🔴 **Червоний рівень**: пряма загроза (ракети, шахеди/БпЛА тощо).
  - 🟡 **Жовтий рівень**: підвищена увага (наприклад, зліт авіації/МіГ-31К, попередження).
  - 🟢 **Відбій**: спокійна ситуація.
- **Локалізація інтерфейсу**:
  - Підтримка української та англійської мов із можливістю явного перемикання в налаштуваннях або використання системної мови за замовчуванням.
  - Форматування часу подій у часовому поясі пристрою (час доби для сьогоднішніх подій, дата + час для попередніх).
- **Фонова служба переднього плану (Foreground Service)**:
  - Працює з `foregroundServiceType="specialUse"` (Target SDK 36), що запобігає примусовій зупинці служби системою через 6 годин (ліміт для `dataSync` в Android 15) та забезпечує цілодобовий безперервний моніторинг тривог.
  - Підтримує постійне WebSocket-з'єднання з сервером NEPTUN незалежно від стану активності, блокування екрана чи вивантаження UI з останніх задач.
  - Автоматичне перепідключення з експоненційним бекоффом (від 2 до 30 секунд).
  - Асинхронний REST fallback (`GET /api/v1/alerts`) на базі сучасного OkHttp 5 та Kotlin Coroutines (`okhttp-coroutines` / `executeAsync`) під час перепідключення для актуалізації статусу.
- **Автоматичне відновлення моніторингу після перезавантаження (`BootReceiver`)**:
  - Відновлення роботи фонової служби при старті системи (`BOOT_COMPLETED`), швидкому перезавантаженні (`QUICKBOOT_POWERON`) та після оновлення застосунку (`MY_PACKAGE_REPLACED`).
  - Служба відновлюється автоматично, якщо глобальний моніторинг увімкнено користувачем у налаштуваннях.
  - Реалізовано через асинхронний `goAsync()` у межах дозволених винятків запуску Foreground Service з фону в Android 12–15.
- **Контроль надійності фонової роботи та оптимізації батареї**:
  - Інформаційна картка у «Загальних налаштуваннях» зі статусом оптимізації заряду.
  - Можливість в один дотик надати виняток з оптимізації батареї (`ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`) для запобігання агресивному примусовому присиплянню застосунку на оболонках OEM (HyperOS/MIUI, OneUI тощо).
- **Синхронізація з годинником**:
  - Прапорець у налаштуваннях кожного профілю для вибору, які саме регіони передаються на годинник.
  - Автоматична передача пакету синхронізації через Wearable Data Layer.
  - Обробка повідомлень ручного запиту синхронізації з годинника.

### 2. Додаток для смарт-годинника (`:wear`)
- **Ускладнення для циферблатів (Wear OS Complications)**:
  - Реалізовано службу `AlertComplicationService` з підтримкою типів `SHORT_TEXT` та `LONG_TEXT`.
  - **Налаштування екземпляра ускладнення**: активність `ComplicationConfigActivity` дозволяє обрати, який саме із синхронізованих профілів показуватиме кожне окреме ускладнення на циферблаті.
  - Відображення поточного статусу та піктограм:
    - 🔴 `ТРВ` / `ALR` — тривога червоного рівня.
    - 🟡 `ЖОВ` / `YEL` — тривога жовтого рівня.
    - 🟢 `ОК` — відбій.
    - ⚪ `—` — відсутність даних або застарілий статус (stale > 15 хв).
- **Автономний екран деталей**:
  - Індикація статусу, типу тривоги, причини загрози (reasons), часу початку та часу останньої синхронізації.
  - Кнопка «Синхр.» для миттєвого оновлення даних зі смартфона.
- **Фоновий слухач**:
  - Миттєве кешування отриманих від смартфона даних.
  - Автоматичне надсилання запиту на перемальовування ускладнень на циферблаті.

## Джерело даних та застереження (NEPTUN)

> **Застереження щодо безпеки**:
> NEPTUN є інформаційним агрегатором, а **не** офіційною державною системою оповіщення. Дані формуються з відкритих і сторонніх джерел та можуть містити неточності або затримки. Застосунок не замінює державні сигнали повітряної тривоги цивільного захисту. Завжди орієнтуйтеся на офіційні сирени та повідомлення органів влади.

## Модулі проєкту

- **`:shared`** — загальна Kotlin-бібліотека (JVM 17):
  - Доменні моделі `AlertStatus`, `Profile`, `AlertLevel`, `WatchSyncData`.
  - Моделі DTO для Neptun API (`NeptunAlertsResponse`, `NeptunOblastAlert`, `NeptunRaionAlert`).
  - База 25 областей та районів України (`DefaultRegions`).
  - Утиліта форматування локального часу подій `EventTimeFormatter`.
  - Константи Wearable DataLayer (`WearConstants`).
  - Контракт та фасад логування (`LogBackend`, `AppLog`) на базі Dependency Inversion із нульовими накладними витратами у релізних збірках (`inline` та `() -> String`).
- **`:core-android`** — спільна Android-бібліотека (`ua.alerts.core`):
  - Спільна інфраструктура для Android-застосунків (реалізація `AndroidLogBackend` на базі `android.util.Log` та ініціалізатор `AndroidLogInitializer`).
- **`:mobile`** — застосунок для смартфона (`ua.alerts.mobile`, namespace `ua.alerts.mobile`, app ID `ua.alerts.neptun`):
  - Повний клієнт моніторингу тривог, UI на Jetpack Compose, фонова служба FGS та синхронізація Wearable Data Layer.
  - Автоматичне відновлення моніторингу після перезавантаження (`BootReceiver`) та контроль оптимізації батареї (`BatteryOptimizationHelper`).
  - Ініціалізація `AndroidLogInitializer` при старті застосунку (`AlertApp`).
- **`:wear`** — застосунок для Wear OS (`ua.alerts.wear`, namespace `ua.alerts.wear`, app ID `ua.alerts.neptun`):
  - Автономний інтерфейс на Wear Compose, ускладнення для циферблатів та фоновий слухач синхронізації.
  - Ініціалізація `AndroidLogInitializer` при старті застосунку (`WearAlertApp`).

## Налаштування підпису релізних збірок

Обидва модулі використовують єдиний keystore для підпису релізних APK. Секретні ключі та паролі ніколи не комітяться до репозиторію.

### Параметри конфігурації
| Властивість | Змінна середовища | Опис | Приклад значення |
|---|---|---|---|
| `RELEASE_STORE_FILE` | `RELEASE_STORE_FILE` | Шлях до `.jks` файлу | `./keys/alerts-release.jks` |
| `RELEASE_STORE_PASSWORD` | `RELEASE_STORE_PASSWORD` | Пароль до сховища ключів | `secret_store_pass` |
| `RELEASE_KEY_ALIAS` | `RELEASE_KEY_ALIAS` | Аліас ключа (за замовчуванням `alerts`) | `alerts` |
| `RELEASE_KEY_PASSWORD` | `RELEASE_KEY_PASSWORD` | Пароль до ключа | `secret_key_pass` |

### Способи передачі параметрів
1. **Файл `signing.properties` у корені проєкту (рекомендовано для локальної розробки)**:
   Скопіюйте шаблон:
   ```powershell
   Copy-Item signing.properties.example signing.properties
   ```
   Та вкажіть дійсні значення у створеному файлі `signing.properties` (цей файл додано до `.gitignore`).
2. **Файл `local.properties` у корені проєкту**:
   Параметри можна також додати безпосередньо у локальний `local.properties`.
3. **Змінні оточення**:
   ```powershell
   $env:RELEASE_STORE_FILE="C:\path\to\alerts-release.jks"
   $env:RELEASE_STORE_PASSWORD="password"
   $env:RELEASE_KEY_ALIAS="alerts"
   $env:RELEASE_KEY_PASSWORD="password"
   ```

Якщо релізні параметри не вказані, релізна збірка формується без підпису або використовує стандартний fallback.

## Збірка проєкту

### Вимоги до середовища
- **OS**: Windows (підтримується також macOS / Linux).
- **JDK**: Java 17.
- **Kotlin**: 2.4.20.
- **AGP / Gradle**: AGP 9.2.1, Gradle 9.4.1.
- **Android SDK**: `compileSdk = 36`, `minSdk = 26` (Mobile) / `30` (Wear), `targetSdk = 36`.

Перед виконанням команд у PowerShell обов'язково встановлюйте шлях до JDK:
```powershell
$env:JAVA_HOME="%USERPROFILE%\.jdks\jbr-17.0.14"
```

### Команди збірки

#### 1. Запуск unit-тестів
```powershell
.\gradlew.bat test
```

#### 2. Збірка налагоджувальних APK (Debug)
```powershell
.\gradlew.bat assembleDebug
```
- Смартфон: `mobile/build/outputs/apk/debug/mobile-debug.apk`
- Годинник: `wear/build/outputs/apk/debug/wear-debug.apk`

#### 3. Збірка релізних підписаних APK (Release)
- **Збірка релізу для смартфона**:
  ```powershell
  .\gradlew.bat :mobile:assembleRelease
  ```
  Файл: `mobile/build/outputs/apk/release/mobile-release.apk`

- **Збірка релізу для Wear OS**:
  ```powershell
  .\gradlew.bat :wear:assembleRelease
  ```
  Файл: `wear/build/outputs/apk/release/wear-release.apk`

- **Збірка обох релізних APK одночасно**:
  ```powershell
  .\gradlew.bat :mobile:assembleRelease :wear:assembleRelease
  ```

## Встановлення через ADB

Обидва застосунки можна встановлювати вручну без завантаження в Google Play. Зверніть увагу: APK для смартфона та APK для годинника збираються окремо і не є взаємозамінними.

### 1. Перевірка підключених пристроїв
```powershell
adb devices
```
Команда має показати список підключених пристроїв та їх серійні номери/IP-адреси.

### 2. Встановлення застосунку на смартфон
```powershell
adb install -r mobile/build/outputs/apk/release/mobile-release.apk
```
*(Параметр `-r` дозволяє оновлювати вже встановлений застосунок зі збереженням даних).*

### 3. Встановлення застосунку на смарт-годинник (Wear OS)
Для встановлення на Galaxy Watch або інший пристрій Wear OS:
1. На годиннику відкрийте **Налаштування** -> **Про годинник** -> **ПЗ** -> натисніть кілька разів на **Номер збірки**, щоб увімкнути режим розробника.
2. Перейдіть у **Налаштування** -> **Параметри розробника** -> увімкніть **Налагодження через ADB** та **Налагодження через Wi-Fi** (Wireless debugging).
3. Підключіться до годинника з комп'ютера (комп'ютер та годинник мають бути в одній Wi-Fi мережі):
   ```powershell
   adb pair <IP-адреса_годинника>:<порт_спарювання> <код_підтвердження>
   adb connect <IP-адреса_годинника>:<порт_підключення>
   ```
4. Встановіть збірку на годинник, вказавши його ідентифікатор у параметрі `-s`:
   ```powershell
   adb -s <IP-адреса_годинника>:<порт> install -r wear/build/outputs/apk/release/wear-release.apk
   ```

## Налаштування та перший запуск

1. **Налаштування на смартфоні**:
   - Запустіть додаток, надайте дозвіл на надсилання сповіщень.
   - Натисніть **«Додати регіон»** і виберіть потрібну область або конкретний район.
   - У картці профілю перевірте прапорець **«Активний на Galaxy Watch»** для регіонів, які бажаєте бачити на годиннику.
   - Налаштуйте звуки тривоги та відбою (за бажанням).
   - Увімкніть тумблер **«Моніторинг»** у верхній панелі.
2. **Додавання ускладнення на циферблат Galaxy Watch**:
   - Натисніть і утримуйте поточний циферблат на годиннику -> виберіть **«Налаштувати» (Customize)**.
   - Оберіть бажаний слот ускладнення (Short Text або Long Text) -> знайдіть категорію **«Тривоги»** -> оберіть **«Статус повітряної тривоги»**.
   - У вікні налаштування ускладнення оберіть профіль/регіон, для якого відображатимуться тривоги в цьому слоті.
