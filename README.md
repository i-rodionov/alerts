# Neptun Alerts & Galaxy Watch Complication

Мультимодульний проєкт для Android та смарт-годинників Samsung Galaxy Watch (Wear OS 3.0+), який відстежує повітряні тривоги в Україні у реальному часі через відкритий API [neptun.in.ua](https://neptun.in.ua/developers).

## Архітектура додатку

Проєкт реалізовано за надійною розділеною архітектурою (Target SDK 35): життєвий цикл довготривалого WebSocket-з'єднання повністю відділений від життєвого циклу Activity/UI та розміщений у виділеній службі переднього плану (**Foreground Service**).

```
MainActivity / Compose UI
       │
       │ Управління [ON / OFF] та спостереження за StateFlow
       ▼
AlertRepository (In-memory реактивне єдине джерело правди)
       ▲
       │ публікація статусу
AlertForegroundService (Власник WebSocket, сповіщень та синхронізації)
       │
       ├── NeptunClient (OkHttp WebSocket wss://neptun.in.ua/api/v1/stream)
       ├── Логіка реконекту з експоненційним бекоффом (2с..30с)
       ├── Обробка та дедуплікація подій тривоги
       ├── NotificationHelper (Постійне FGS сповіщення + Сигнали тривоги)
       ├── WearSyncManager (Синхронізація з Galaxy Watch через Wearable Data Layer)
       │
       ▼
Neptun API (Потоковий WebSocket + Fallback REST зрізи)
```

### Ключові особливості архітектури:
- **Повна незалежність від UI**: З'єднання та обробка тривог не залежать від стану Activity. Додаток зберігає активне підключення, коли Activity закрита, екран заблоковано або додаток змахнуто зі списку останніх задач (Recent Apps).
- **Foreground Service (Target SDK 35)**: Служба `AlertForegroundService` оголошена з типом `foregroundServiceType="dataSync"`, своєчасно викликає `ServiceCompat.startForeground()`, має прапорець `android:stopWithTask="false"` та повертає `START_STICKY` для автоматичного відновлення при перезапуску процесу системою.
- **Єдине джерело правди (`AlertRepository`)**: Замість ненадійного прив'язування (`bindService` з `BIND_AUTO_CREATE`), яке призводить до витоків пам'яті та блокує зупинку служби, UI та сервіс спілкуються через реактивні `StateFlow`.
- **Явне керування моніторингом**: Користувач може вмикати та вимикати моніторинг безпосередньо з інтерфейсу перемикачем `[ ON / OFF ]`.
- **Розділення станів**: Стан служби відокремлено від стану WebSocket. Система розрізняє 5 чітких станів:
  - `STOPPED` — Моніторинг вимкнено / Службу зупинено
  - `CONNECTING` — Підключення…
  - `CONNECTED` — Підключено (Live)
  - `RECONNECTING` — Перепідключення… (Sync)
  - `ERROR` — Помилка з'єднання
- **Стійке перепідключення**: При втраті зв'язку застосовується обмежений експоненційний бекофф ($2\text{с}, 4\text{с}, 8\text{с}, 16\text{с}, 30\text{с}$ макс.) та REST fallback зрізи (`GET /api/v1/alerts`), щоб не пропустити сигнал тривоги під час відновлення сокета.
- **Чисте завершення**: Зупинка служби коректно закриває WebSocket (код 1000), скасовує спроби повторного підключення, звільняє ресурси, знімає сповіщення і повністю завершує роботу служби (`stopSelf()`).
- **Захист від дублювання**: Запуск служби та підключення сокета ідемпотентні. Події тривог фільтруються для уникнення повторних звукових сигналів при отриманні однакових зрізів.

## Структура модулів

- **`:mobile`** — Companion-додаток для смартфона (`ua.alerts.mobile`):
  - `AlertForegroundService`: Служба переднього плану, що керує підключенням до Neptun, оновлює статусний бар та синхронізує годинник.
  - `AlertRepository`: Реактивне сховище поточного стану моніторингу та тривог.
  - `NeptunClient`: Клієнт OkHttp для WebSocket та HTTP REST snapshot.
  - `WearSyncManager`: Менеджер обміну даними з годинником через Google Play Services DataClient.
  - `SettingsRepository`: Збереження налаштувань (обраний регіон/район, звук, вібрація, статус моніторингу) у Jetpack DataStore Preferences.
  - `NotificationHelper`: Керування каналами сповіщень та звуковими/вібраційними тривогами.
  - UI: Jetpack Compose (`MainActivity`, `MainViewModel`, `HomeScreen`, `RegionSelectScreen`).
- **`:wear`** — Додаток для Samsung Galaxy Watch (Wear OS):
  - **Complication Provider** (`AlertComplicationService`): Підтримка слотів `SHORT_TEXT` та `LONG_TEXT` на циферблатах.
  - Індикація тривоги (🔴 «ТРВ» / час), спокою (🟢 «ОК») та втрати зв'язку (⚪ «—» при відсутності оновлень > 15 хв).
  - Екран деталей (`AlertDetailScreen`) з інформацією про початок загрози та кнопкою ручного запиту синхронізації.
  - Фоновий слухач `WearDataListenerService`, що миттєво оновлює циферблат при зміні даних на смартфоні.
- **`:shared`** — Pure Kotlin бібліотека:
  - Моделі даних `AlertStatus`, `Region`, `District`, DTO відповідей Neptun.
  - Вбудований повний довідник усіх 25 областей та районів України за новим адміністративним поділом.
  - Константи шляхів Wearable DataLayer (`/alert_status`, `/request_sync`).

## Збірка та тестування

### Вимоги до середовища
- Host OS: Windows
- JDK: Java 17
- Android SDK: `compileSdk = 35`, `targetSdk = 35`, `minSdk = 26` (Mobile) / `30` (Wear)

### Команди PowerShell

Завжди встановлюйте `JAVA_HOME` перед запуском Gradle-команд:

```powershell
.\gradlew.bat test
```

- **Запуск усіх unit-тестів**:
  ```powershell
  .\gradlew.bat test
  ```
- **Збірка Debug APK (мобільний додаток + годинник)**:
  ```powershell
  .\gradlew.bat assembleDebug
  ```

## Як запустити та налаштувати

1. Відкрийте проєкт у **Android Studio**.
2. **Запуск мобільного додатку**:
   - Оберіть конфігурацію `:mobile` та запустіть на смартфоні або емуляторі.
   - Надайте дозвіл на сповіщення.
   - Оберіть область або конкретний район.
   - Переконайтеся, що перемикач **«Моніторинг»** увімкнено (статус `Підключено` / `Live`).
3. **Запуск додатку для годинника**:
   - Оберіть конфігурацію `:wear` та встановіть на Galaxy Watch або емулятор Wear OS.
4. **Додавання Complication на циферблат**:
   - На годиннику відкрийте редагування циферблата -> «Налаштувати» (Customize).
   - Оберіть потрібний слот ускладнення -> оберіть «Тривоги» -> «Статус повітряної тривоги».
